## 📊 Free Tier Limits

### Bandwidth: 100GB/month
**What this means:**
- 100GB of data transfer per month
- If your site serves 1MB per visitor:
  - 100GB = 100,000 visitors/month
  - That's ~3,300 visitors/day

**For a restaurant:**
- Average page size: ~500KB
- 100GB = ~200,000 page views/month
- More than enough for most restaurants!

### Serverless Function Execution: 100GB-hours/month
**What this means:**
- Your API routes (like `/api/menu`, `/api/orders`)
- 100GB-hours is a LOT
- Example: If your function uses 128MB RAM:
  - 100GB-hours = 800 hours of execution time
  - That's 33 days of continuous execution!

**For a restaurant:**
- API calls are usually very fast (< 1 second)
- You'd need millions of API calls to hit this limit
- More than enough!

### Build Time: 6,000 minutes/month
**What this means:**
- Time spent building your site
- 6,000 minutes = 100 hours/month
- Each build takes ~2-5 minutes
- That's 1,200-3,000 builds/month

**For a restaurant:**
- You probably deploy a few times per week
- Way more than enough!

## 💵 When Do You Need to Pay?

### Pro Plan: $20/month

**You need Pro if:**
- ❌ You need more than 100GB bandwidth/month

- ❌ You need advanced analytics
- ❌ You need password protection

**For most restaurants:**
- You probably won't need Pro
- Free tier is usually enough!

## 📈 When You Might Need to Upgrade

### If Your Restaurant Grows:
- **Very popular:** 50,000+ visitors/month
- **Large menu:** Many images, high bandwidth
- **Multiple locations:** Need team features
- **High traffic:** Exceeding 100GB bandwidth

**Then consider:** Pro plan ($20/month) or Enterprise

## 🔄 What Happens If You Exceed Free Limits?

1. **Bandwidth:** Site still works, but you'll be asked to upgrade
2. **Build time:** Builds might be slower or queued
3. **Function execution:** Functions still work, but you'll be notified

**Vercel is generous** - they usually give warnings before cutting you off.
